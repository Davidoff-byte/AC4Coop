## 14. Ship-sync jitter and the request lifetime (T16–T18, 2026-11-28 night)
**Jitter cause (read + measured).** With `ShipClassBind=2` the bound hull was warped once per applied snapshot (~10 Hz)
and the hull's own `ShipPhysicComponent` (→ `AbstractWatercraftPhysicComponent` → `RigidBodyComponent`, class names
from the slot-5 descriptors in dump 28300; 22 components on an AI ship incl. `AIComponent`, `SailManager`,
`WatercraftAttributes`) re-drove the entity from its rigid body in between. Per-frame warps alone were pulled back
0.7–0.9 m/frame (p95 2.0 m). Fix: `[Coop] ShipInterp` (docs/design/ship-interp.md): host-timestamped ring per
(hull, host ship), per-frame warp at `now − 200 ms` on the host timeline, and `m_DriveEntity = false` on the hull's
`ShipPhysicComponent` while driven (the remedy the driven guard mirrors already use). T17 at sea: drift 0.000 m.
**Crash H (T16, guest 29212, first fast travel).** EIP in freed memory from the unload loop (`sub_718650` → listener
vt[5] `0x138F9F0` → `sub_48F5D0` → `sub_48BAE0` element vt[1]); the element was our replay request FC15F100 (owner =
our private owner inside AC4Coop.asi). Request lifetime (IDA): submit sets flag `+0x24 = 1` (owner-kept); the naval
client (vt 0x0270B310) releases a request to its type-3 list after completion only when owner vt[19]() is true
(`sub_1982900`/`sub_1982940` → `sub_5BCBE0`); the naval owner's own vt[19] returns 0 because it keeps and disposes its
requests (and its specs: `sub_1978B50` builds a fresh spec per spawn and sets `req+0x31 = 1`, the request dtor frees
it). Fix: private owner vt[19] = true. T17: 4 replays before the first fast travel, 2 travels, no crash, [19] 9/9.
**Crash I (T17, guest 28276, at sea; then T18 guest + host 16964).** AV at `0x1425954` inside the naval owner's own
spawn routine `sub_1978B50`, which walks the owner's request container (object+0x0C, count +0x12) and calls each
request's vt[2]. First read as "not tied to our objects"; **corrected** by the T18 host dump: the container held
exactly our 3 replay requests, already freed — `sub_79B8D0` appends a request to `[req+0Ch]+4` (`sub_48A390`), and our
submits then carried the real owner. Fix: submit with the private owner (its container is our static object), then
CAS `req+0x0C` to the real owner for the build-now path; DetSet swaps it back. The same T17 run had also replayed 9
class-1/2 hulls for one class-3 host ship (no class-3 spec on the guest): a class miss now counts toward the per-class
give-up, and library specs of another known class are refused.
**Interp pops (T17).** 43 pops > 1 m in 15 windows: rings keyed by hull alone mixed two host ships after a rebind
(drift spike 1529 m), and a new binding was snapped to the newest sample, then rendered 200 ms behind (backward step).
Fix (T18): ring per (hull, host ship) and placement by the per-frame writer; pops counted only on settled rings.
NPCs (same run): `[Own] smooth` up to 3443 moving frames per window, stalled 0, pops > 0.5 m 2 in total.

## 15. Smooth ships, second pass, and the released-request crash (2026-11-28 04:30–06:20)

`sub_1991F70`), the per-tick walk of the client's released list (+0x4C): request vt[2] → spec, `sub_4EFD00(spec)` =

sat inside `EntitySyncTick`'s slow tick (every 6th frame). It now runs from `OnFrameInner` on the guest every frame.

the frame that drained them (`PuppetHostTime=0`), and its Z was the newer sample's. New `[Coop] ShipGhostInterp`
(docs/design/ship-interp.md): the sender's capture time (`hostTimeMs`), own min-offset clock, per-frame sampling.
**Metric fix (synthetic negative control).** `[ShipSmooth]` stamped the hull position it read at frame k (left by frame
k−1) with frame k's time. On perfectly linear motion (8 m/s) with frame dt ±2/4/8 ms that stamp reports 87/94/97 %
frames > 15 m/s²; stamped with the frame that produced it, 0 %. Fixed in asi 117D9734 (both modes); `[GhostSmooth]`
was aligned from the start.
