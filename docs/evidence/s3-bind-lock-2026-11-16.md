# S3: locked one-to-one guard links, wide bind on with FightIntents (2026-11-16)

Follow-up to `s3-guard-identity-2026-11-16.md`, as requested in the AU-RW session's reply:
- wide bind on whenever `FightIntents` is on, with an ini override, read once;
- a link, once made, never re-picked;
- one-to-one assignment, nearest pairs first, same guard type only.

Build: commit `d82af41`, asi c0be5c6bbe2523d3a5e3351a371ea2c1ac3c1f17e73d10a3fa2a0fa057cf3d9c. Two copies via `two_copy.ps1`
with only `NativeReplica=0 FightIntents=1 IntentLane=1` set: radius and lock come from the new defaults. Host 25964,
guest 14988, both moved to the soldier area (36, -74).

## What changed (src/phase1.cpp)
- **`WideBindRadiusM`:** read once. Default 12 when `[Coop] FightIntents=1`, else 0; an explicit `BindRadiusM` overrides.
  `BindRequireArch` is also read once. Before, both were re-read every 2 s, which dropped the radius to 0 when the runner
  restored the ini.
- **`[Coop] BindLock`** (default follows FightIntents, read once). In `GuestObjAdd`:
  - a live link is never re-pointed (`blocked repoint`);
  - a body that already plays another live host guard is not given a second one (`blocked double`);
  - a link is replaced only when its body is gone (`replacedGone`).
- What was already there: the wide-bind prepass assigns nearest pairs first (exact ≤ 1.5 m, then ≤ R), same archetype
  only, one body per need per run, and skips bodies already linked (`GuestObjOfEnt`).
- **`[Bind]`** line on the guest every 5 s: `linked`, `doubleNow` (a body appearing under two host ids right now),
  `stale(bodyGone)`, added, repointed, blocked, replacedGone, dropped(evicted, forgotten).
