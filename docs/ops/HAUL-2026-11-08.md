# Long haul — 8 Nov 2026: what is left and in what order

State at the start of this shift: **the ASI crashes the game within ~15 s of launch; vanilla does
not.** Everything in-game is blocked behind that, so it is item 1.

---

## 1. The launch crash — bisected, and the bisect was negative

Automated harness `ops/tools/bisect_crash.ps1`: sets ini flags, launches via Steam, watches the
process, kills, next variant. Seven variants, all against ASI `E2934659D464`:

```
V0 baseline                 crashed ~20 s
V1 deref guards off         crashed ~10 s
V2 action guard off         crashed ~10 s
V3 pad hook off             crashed ~10 s
V4 windowed hook off        crashed ~15 s
V5 net off                  crashed ~10 s
V6 everything off           crashed ~10 s
```

All seven, same signature: `module: unknown`, `0xC0000005` then `0xC000041D`, fixed offset
`0x5bc725c0`. Every run wrote a phase1 log (716–735 B) that stops at the same line.

**Conclusion: the crash is not gated by any ini flag.** The ini only gates some hooks. The ones
installed unconditionally at `DllMain` are not covered by the matrix:

- `InstallFrameHook` (the per-frame detour — the entry point for every system in the mod)
- `SgmDetour` on `SetGlobalMatrixInternal` (`0x528200`)
- the windowed/style detour's install path (even with `ForceWindowedMs=0`, the detour may install)
- the `CreateMutexW` IAT patch

**Next bisect must be compile-time, not ini-time:** add `[Coop] InstallHooks` (default 1) read in
`DllMain` *before* any detour, and build variants in this order:

1. hooks off entirely (load, log, do nothing) → if this runs, the ASI is fine and a hook is guilty
2. frame hook only
3. frame + SGM
4. frame + SGM + windowed
5. all

That is five builds and five launches, ~10 minutes, and it names the guilty hook with certainty.

**Why this is first:** nothing else can be measured in-game until it is green. It also matters for
the two-machine test — every fix made since 17:04 is unverified *because* the game will not run with
the mod.

## 2. The Gamer/avatar experiment — paused, not abandoned

`ProbeGamerStructure` exists (in the `gamer-probe` stash, and in `AC4Coop.asi.off`). It is:
- a read-only walk of the World's first 8 KB, checking each pointer against the PS3-derived
  `GamerCollection` / `Gamer` layout, reporting a HIT only when a gamer's avatar list contains the
  local player entity;
- bounded, `readable()`-guarded, one shot at frame 300, behind `[Coop] GamerProbe`.

It cannot run until item 1 is green. When it can, the outcome decides stealth:

| result | meaning |
|---|---|
| `HIT … PLAYER_MATCH` | a Gamer owns the player entity → registering a second avatar is plausible |
| `candidates=0 hits=0` | the layout guess is wrong → back to address hunting, or cut stealth |

## 4. Facts learned this week that the plans still need to absorb

| fact | where it bites |
|---|---|
| `kind` is the entity class (2 = character), **not** hostility; fighters are `kind=2` + role | `SyncEnemiesOnly` fixed; `PLAN-COOP-V2` P5 text still says `kind==3` |
| `WeaponComponent` / `MapIconBehaviorGuard` **never attach** — `armed=0` on 300+ combat bodies | the "armed" test is dead weight, remove before it misleads |
| guards do not perceive the ghost: `stage=1` at `dPeer=0.1 m`, control fires at `dPlayer=1–3 m` | P6 FAIL; stealth is cut unless the Gamer path works |
| counters are per 5 s window ≈ 100 captures, not per frame | every census number must be divided by `s_capWin` |
