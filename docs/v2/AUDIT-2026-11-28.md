**Hidden defects in the shipped configuration** (read from code, consistent with the owner's reports):
- `PuppetFightStim` cannot fire while `PuppetFightCarry=2`: `FightIntentApply` returns at phase1.cpp:12808 before `PfsPost`
  (12849-12861). This is the guest-combat regression ("npcs will not run to attack").
- `SpawnLibLateRestore` is read only when a `SpawnLib` key exists (spawn_lib.cpp:379-386). The install has
  `ShipSpawnReplay=1` and no `SpawnLib` key, so the borrowed slot is restored early (spawn_lib.cpp:435): the one-frame jump

  The install has `ShipClassBindSteal=1`, the setting behind the one open guest crash (spawn-lib s8).

  `HookSgm` is the reverse (1 in code, 0 in the inis). `Net.PeerPort` 47801 in code vs 47802 in the template.
- Nine guard hooks install when their key merely exists (presence gating), whatever its value.

## 3. Code structure and hazards
**Threading.** The per-Human update hook (FrameDetour -> OnFrame, phase1.cpp:19262 -> 18085) runs on up to 16 worker threads
("executed on 16 different worker threads in one session", 9254-9256). OnFrameInner runs on whichever worker updates the
local player (`s_playerWorkTid`, 18337). The SetGlobalMatrix detour runs on up to 19 job threads (1464-1465). The dllmain
poll thread (20 Hz) and the net RecvThread are ours. Comments at phase1.h:5-7 and 19674 still say "main thread".
**Unsynchronised cross-thread globals:**
- the ghost pose arrays: written by the player work, read in the SGM detour, so quaternions can tear;
- `g_ghostShip`, `g_localShipZ`, `s_ghCmdLw`;
- the lazy ini read of `s_shipPeerZ` in the SGM detour;
- `ShipClassBindMode()`, which does a read-modify-write plus an ini read on job threads;
- the SGM probe statics `s_vt[40]`/`s_n` (two threads can pass `s_n < 40`: out-of-bounds write);
- `NavNoAutoSinkPost` reads `s_nav[]` without `s_navLock` (6550-6555);
- poll-thread test state read by the player work;
- `OwnFlag` statics;
- `puppet_listener` calls engine functions and writes health off the game thread.

**SEH.** The whole player work runs inside `__try { OnFrameInner(...) }` (18102); more wrappers at 18091, 18092, 18097,
18350. Only nine calls were moved out (the deferred block 18144-18154). Still under SEH:
- the hull setter 0x01225A10 (coord_sync.cpp:161, phase1.cpp:1369, 11793);
- 0x01207960 (4788, 5083);
- the helm lever 0x011FE840 (11619);
- the sail setter 0x01220960 (11421);
- the event post 0x0064A020 (puppet_stim.cpp:86, 113, 158);
- 0x10EFC30 / 0x18BD690 / 0x64D8C0 (player_damage_probe.cpp:413-498, with EnterCriticalSection at 496);
- SetLife 0x19FB4C0 (16008, 8924, 11100, 11158);
- the spawn submit 0x00569560 (spawn_census.cpp:533, 681);

- entity build (772-836; `PuppetBuildRecover` exists because "the unwind leaked");
- SetGlobalMatrixInternal at 7 sites.

`t_odRelay` is not reset in the `__except` at 15959-15962 and 8930 (it is at 15972 and 11105). The lock rule exists only in
code comments and ship-spawn-replay.md:28-31.

## 4. Networking and authority
**Protocol.** Proto 18, one UDP socket, the first 4 bytes pick the lane:
- `AC4C` PlayerState: 576 B, every sender frame, newest wins plus a 16-deep queue;
- `AC4E` entity snapshots:
  - 36 B header; records of 16 B + changed fields; chunks up to 1170 B;
  - `SnapshotHz` 20, but it is checked every 6th frame, so about 5-10 Hz;
  - deltas with a full resend every 64 packets;
  - no "removed" record;
- `AC4I` intent lane: the only reliable lane, last value per (object, channel), 512 keys, resend 100 ms;
- `AC4P` poses, `AC4K` PeerClock, `AC4L` lobby;
- channels IC_1..15: 3 never published; several kinds share one key; the 15 numbers are used up.

**Link state** (bug W-P3-1, phase1.cpp:18832): `peerPresent = rawSameWorld && (now - lastFreshMs) < kPeerLiveMs && timerOk`,
with `haveRaw` = "a packet was drained this frame" (`PeerLastPacket=0`). Any frame without a new packet is "link down",
about 2300 flaps per 10 min in every build since 11-24. The puppet spawn/drive block is skipped on those frames (19002).
The fix `1c49920` was never enabled.

**Authority as built.**

| object | owner | wire | receiver |
|---|---|---|---|
| local player | itself | PlayerState every frame | - |
| peer's character (puppet) | the peer | PlayerState | a second Edward, collision off, driven from a 100 ms local-time buffer; host guards see it only through patched sight checks |
| guards/NPCs | host, only what its game has loaded | up to 32 records per snapshot + IC_ACTION / IC_BRAIN / IC_ATK_* / IC_PDAMAGE | the guest binds one of its own bodies (slot, spawn key, object id or position 1.5 / 12 m), turns its AI off and drives it; guest damage goes to the host as a request |
| ship crews | host | crew key | through the ship table |
| AI ships | host (within 1000 m of the guest) | snapshot records | nearest free guest ship of the same class within 3 km, else a replay hull; moved every frame, 400 ms behind |
| peer's ship (ghost) | the peer | ship fields in PlayerState | a clone of a local ship, physics/AI off, 250 ms behind |
| boarding objectives | host | IC_COORD fields 3-8 | raw state writes; boarding start not sent |
| forts | nobody | - | - |
| world | host: time of day 1 Hz | - | the guest sets its clock past 0.05 h |

**Inconsistencies.**
- **Identity:** 7 schemes, none portable, no registry:
  - host slots vs list indices;
  - per-process object ids ("on the guest the same id can name a DIFFERENT entity", 13725);
  - two kinds of made-up ids;
  - spawn-point keys;
  - ship class;
  - CoordSync key 0 / `TODH`;
  - position matches at 1.5 / 4 / 12 m.
- **Clocks:** 5 estimates of the host clock (OwnOffset, ScbFeedOffset, the ghost clock, PuppetHostTime=0, PeerClock), and
  `hostMs` on intents has 5 meanings.
- **Writers:** up to 3 per object:
  - a bound AI ship: interpolator + SGM hook + its own AI;
  - a guest guard: snapshot + per-frame writer + legacy write + Brain replay;
  - the guest's own Jackdaw: its physics + CoordSync key 0 + helm.
- **Proximity:** the host syncs only what is loaded around the host (NPCs within 60 m of the guest and 80 m of the host). A
  guest far away gets unsynced local AI; its kills go out once and land on the "nearest soldier within 4 m" (16328).
- **Roles:** `[Net] Mode` and `[Coop] EntityHost` are separate settings. Multi-guest has `g_peers[3]`, but every lane uses
  entry 0.
- **Stale docs:** STATUS.md:55 (ini values), intention-lane.md:3 ("not wired").
